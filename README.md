Project Name: 

    兵棋推演沙盒

專案內容說明: 

    本專案為一款兵棋推演的後端路徑規劃系統。透過 FastAPI 與 OSRM 的整合，提供具備真實道路限制的戰略部署、交戰與移動模擬。系統支援非同步的座標路徑計算與資料處理，可輸出最佳行軍路線，作為兵棋推演系統的核心運算模組。

主要檔案結構與用途: 

    model: 
        config.py:          管理遊戲機制的常數（如補給範圍、燃油消耗機制、伺服器 Tick 設定），並定義預設的兵種數值模板（步兵、坦克、飛機、船艦、機場），方便後續擴充與平衡調整。
        math_utils.py:      Haversine公式計算
        schemas.py:         使用 Pydantic 定義資料結構，包含核心實體（如 Unit, BattleState）、事件日誌（戰鬥與燃油消耗），以及 API 的請求與回應格式。
        state_manager.py:   戰場狀態與兵種設定管理（存取 state.json 與 units.json），並維護近期的戰鬥與燃油事件紀錄。

    combat.py:              戰鬥系統。處理單位的傷害計算（包含距離衰減與兵種相剋），以及自動接戰與反擊的判定邏輯。
    engine.py:              燃油與後勤系統。專門處理空軍單位的燃油消耗、自動尋找最近機場返航以及補滿燃料的邏輯。
    game_loop.py:           核心計時器。透過異步迴圈，定期觸發所有單位的移動、追擊、燃油消耗與自動戰鬥邏輯。
    movement.py:            移動系統。根據單位速度與 OSRM 提供的路徑節點，計算每個 Tick 的經緯度推進；並包含鎖定目標的追擊邏輯。
    osrm.py:                外部路徑 API 客戶端。利用 httpx 發送非同步請求至 OSRM 引擎，取得符合真實路網的座標節點。

    routes.py:              定義所有 RESTful API 端點。負責接收前端使用者的操作指令（如部署、移動、改變交戰規則、手動開火等），並更新後端狀態。

    main.py:                主程式。初始化 FastAPI 實例與 CORS 設定，及管理生命週期。

執行方式: 

    執行 main.py (因規定不提交前端，故已將其中部分註解以避免影響)
